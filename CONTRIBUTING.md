# Contributing

Thanks for taking the time to contribute. This project is small on purpose — please keep changes focused and readable.

## Getting set up

```bash
npm install
npm run db:local
npm run dev
```

The site runs at http://127.0.0.1:8788 and the dashboard at `/dashboard`.

## Before you open a pull request

1. **Test locally.** Open the site *and* the dashboard, and exercise the section you touched.
2. **Check the security rules.** Never introduce SQL that is built from user input. Table and column names must come from the whitelist in `functions/api/[[route]].js`, and all values must be bound parameters.
3. **Do not commit secrets.** No API keys, tokens, `.dev.vars` or `.env` files.
4. **Keep `dist/` out of commits.** It is generated by `npm run deploy`.
5. **Match the existing style.** Two-space indentation in JavaScript, single quotes, and no build step.

## What makes a good pull request

- One concern per pull request.
- A short description of the problem and why your change fixes it.
- Screenshots for anything visual.
- An explanation if you add a new API route, including who can call it and what it validates.

## Reporting a bug

Include:

- What you did, what you expected, and what happened.
- Your Node version and whether you were running locally or deployed.
- Any console or `wrangler` output.

## Suggesting a feature

Open an issue describing the use case first. This template deliberately stays dependency-light, so proposals that add a build step or a large framework will usually be declined.
